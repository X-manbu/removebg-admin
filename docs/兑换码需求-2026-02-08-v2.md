# 点数与兑换码系统需求文档 v2.0

**文档版本**: v2.0
**创建日期**: 2026-02-08
**项目**: removebg-server 人像抠图 API 服务

---

## 1. 需求概述

### 1.1 背景

当前智能抠图接口 `/api/process/matting` 已实现微信登录鉴权，但缺乏防刷机制。为防止用户恶意盗刷接口，需要引入点数消费体系和兑换码充值系统。

### 1.2 目标

1. **防止接口盗刷**：通过点数扣费机制限制用户调用频率
2. **用户增长激励**：新用户赠送初始点数，降低使用门槛
3. **运营灵活性**：后台可配置初始点数，批量生成兑换码进行运营活动
4. **系统可扩展性**：兑换码模块设计为通用奖励系统，支持扩展到其他业务场景

### 1.3 核心原则

- **低耦合高内聚**：兑换码模块独立封装，可复用
- **配置驱动**：关键参数支持后台配置，无需重新部署
- **审计完备**：所有点数变更、兑换操作均有日志记录

## 2. 功能需求

### 2.1 用户点数机制

#### 2.1.1 新用户初始点数

| 功能项 | 说明 |
|-------|------|
| 触发时机 | 用户首次登录（微信授权成功后） |
| 默认值 | 通过后台配置，默认 10 点 |
| 配置方式 | 新增 `/api/admin/config` 接口，支持动态修改 |
| 存储位置 | `users.points` 字段 |

**业务流程**：
```
用户微信登录 -> 检查是否新用户（openid 不存在）-> 创建用户记录 -> 赠送初始点数 -> 记录点数日志 -> 返回 JWT token
```

#### 2.1.2 抠图接口扣费

| 功能项 | 说明 |
|-------|------|
| 扣费接口 | `POST /api/process/matting` |
| 扣费规则 | 固定扣除 1 点/次 |
| 扣费时机 | 调用百度 API 成功后（失败不扣费） |
| 余额不足 | 返回错误码 3001，提示用户点数不足 |

**错误码定义**：
```
3001 - 点数不足，请充值后再试
```

#### 2.1.3 用户点数查询

用户可查看当前点数余额和近期点数变动记录。

---

### 2.2 兑换码系统

#### 2.2.1 兑换码生成（管理员）

| 功能项 | 说明 |
|-------|------|
| 接口路径 | `POST /api/admin/redemption-codes/generate` |
| 权限要求 | 管理员角色 |
| 生成参数 | 数量、面额、过期时间、备注（可选） |
| 返回结果 | 生成的兑换码列表（支持导出） |

#### 2.2.2 兑换码兑换（用户）

| 功能项 | 说明 |
|-------|------|
| 接口路径 | `POST /api/redemption-codes/redeem` |
| 权限要求 | 已登录用户 |
| 请求参数 | 兑换码字符串 |
| 兑换逻辑 | 验证码有效性 -> 检查状态 -> 增加用户点数 -> 标记码已用 -> 记录日志 |
| 错误处理 | 码不存在/已过期/已使用/格式错误 |

**兑换码规则**：
- 每个码仅可使用 1 次
- 支持设置过期时间（可选，由管理员生成时指定）
- 格式：16 位随机字母数字（大写），如 `AB3D9F2E7C1H4K8M`

#### 2.2.3 兑换码查询（管理员）

| 功能项 | 说明 |
|-------|------|
| 接口路径 | `GET /api/admin/redemption-codes` |
| 权限要求 | 管理员角色 |
| 查询条件 | 状态（全部/未使用/已使用/已过期）、批次、时间范围 |
| 返回内容 | 码列表，含状态、使用信息等 |

| 字段 | 类型 | 默认值 | 说明 |

| role | VARCHAR(20) | 'user' | 用户角色：user/admin |

#### 3.1.2 新增表：`system_config`

```sql
CREATE TABLE system_config (
  id SERIAL PRIMARY KEY,
  key VARCHAR(50) NOT NULL UNIQUE,
  value TEXT NOT NULL,
  description VARCHAR(255),
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_by INTEGER REFERENCES users(id)
);

-- 初始配置
INSERT INTO system_config (key, value, description) VALUESccc
  ('initialPoints', '10', '新用户初始点数'),
  ('mattingCost', '1', '每次抠图扣费点数'),
  ('defaultCodeExpiryDays', '30', '兑换码默认过期天数');
```

#### 3.1.3 新增表：`redemption_codes`

```sql
CREATE TABLE redemption_codes (
  id SERIAL PRIMARY KEY,
  code VARCHAR(20) NOT NULL UNIQUE,
  reward_type VARCHAR(20) NOT NULL DEFAULT 'points',
  reward_value INTEGER NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'active',
  expires_at TIMESTAMP,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER REFERENCES users(id),
  used_by INTEGER REFERENCES users(id),
  used_at TIMESTAMP,
  batch_name VARCHAR(100),
  metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_redemption_codes_code ON redemption_codes(code);
CREATE INDEX idx_redemption_codes_status ON redemption_codes(status);
CREATE INDEX idx_redemption_codes_batch ON redemption_codes(batch_name);
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| code | VARCHAR(20) | 兑换码（唯一） |
| reward_type | VARCHAR(20) | 奖励类型：points/vip/coupon |
| reward_value | INTEGER | 奖励值（点数/天数等） |
| status | VARCHAR(20) | 状态：active/used/expired |
| expires_at | TIMESTAMP | 过期时间（NULL 表示永不过期） |
| batch_name | VARCHAR(100) | 批次名称，便于管理 |
| metadata | JSONB | 扩展字段 |

#### 3.1.4 新增表：`point_logs`

```sql
CREATE TABLE point_logs (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  change_amount INTEGER NOT NULL,
  balance_before INTEGER NOT NULL,
  balance_after INTEGER NOT NULL,
  reason VARCHAR(50) NOT NULL,
  related_id INTEGER,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_point_logs_user ON point_logs(user_id);
CREATE INDEX idx_point_logs_created_at ON point_logs(created_at);
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| change_amount | INTEGER | 变更数量（正数增加，负数减少） |
| balance_before | INTEGER | 变更前余额 |
| balance_after | INTEGER | 变更后余额 |
| reason | VARCHAR(50) | 变更原因：initial/matting/redemption/admin |
| related_id | INTEGER | 关联记录 ID（如兑换码 ID） |
| metadata | JSONB | 扩展字段 |

#### 3.1.5 新增表：`redemption_logs`

```sql
CREATE TABLE redemption_logs (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  redemption_code_id INTEGER NOT NULL REFERENCES redemption_codes(id),
  code VARCHAR(20) NOT NULL,
  reward_type VARCHAR(20) NOT NULL,
  reward_value INTEGER NOT NULL,
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP

CREATE INDEX idx_redemption_logs_user ON redemption_logs(user_id);
CREATE INDEX idx_redemption_logs_code ON redemption_logs(code);
CREATE INDEX idx_redemption_logs_created_at ON redemption_logs(created_at);
```

### 4.3 修改现有接口

#### 4.3.1 抠图接口扣费

现有 `POST /api/process/matting` 接口增加点数校验逻辑：

**变更流程**：
1. 鉴权通过后，检查用户点数是否 >= 1
2. 如果点数不足，直接返回错误码 3001
3. 调用百度 API 处理图片
4. 处理成功后扣除 1 点，记录点数日志
5. 返回处理结果

**点数不足响应**：
```json
{
  "code": 3001,
  "message": "点数不足，请充值后再试",
  "data": {
    "currentBalance": 0
  }
}
```

#### 4.3.2 登录接口赠送初始点数

现有 `POST /api/auth/login` 接口增加新用户判断逻辑：

**变更流程**：
1. 微信授权成功后，检查 openid 是否已存在
2. 如果是新用户，获取系统配置的 `initialPoints`
3. 创建用户记录，设置初始点数
4. 记录点数日志（reason: initial）
5. 返回 JWT token

```typescript
  rewardType: RewardType;
```

## 6. 非功能需求

### 6.1 安全性

| 需求 | 实现方式 |
|-----|---------|
| 兑换码防刷 | 每个码限用 1 次，使用后状态变更 |
| 接口鉴权 | 所有接口需 JWT 验证 |
| 管理员隔离 | 管理接口增加角色校验 |
| 防重放攻击 | 兑换接口使用数据库事务保证原子性 |
| 审计日志 | 所有敏感操作记录操作人和时间 |

### 6.2 性能

| 需求 | 实现方式 |
|-----|---------|
| 兑换码查询 | 索引优化（code 字段唯一索引） |
| 批量生成 | 使用数据库批量插入 |
| 点数扣费 | 数据库行锁防止并发问题 |
| 日志查询 | 分页 + 时间范围索引 |

### 6.3 可维护性

| 需求 | 实现方式 |
|-----|---------|
| 模块化 | 兑换码服务独立封装 |
| 类型安全 | TypeScript 强类型定义 |
| 错误处理 | 统一错误码和异常处理 |
| 文档 | 接口文档同步更新 |

### 6.4 可扩展性

| 需求 | 实现方式 |
|-----|---------|
| 奖励类型扩展 | `rewardType` 枚举可扩展 |
